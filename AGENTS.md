# crawl-skku Agent Guide

## Overview

`crawl-skku` is an installable Python package and FastAPI application that fetches public SKKU board posts and academic-calendar data, then exposes normalized Pydantic models.

- Python: 3.11 or newer
- Package manager: `uv`
- ASGI application: `crawl_skku.api:app`
- CLI: `crawl-skku serve --host 127.0.0.1 --port 8000`
- Official references: [FastAPI](https://fastapi.tiangolo.com/) and [uv](https://docs.astral.sh/uv/)

## Architecture

Article data flow:

```text
router -> source service -> SQLite cache -> upstream fetch -> source parser -> Pydantic response
```

Calendar data uses the same pattern. Source-specific code belongs under `src/crawl_skku/article/{source}/` or `src/crawl_skku/calendar/{source}/`; keep URLs, selectors, and board numbers local to that source.

Supported article source identifiers are `root`, `sw`, `skb_swuniv`, `cse`, and `sco`. Preserve the existing `/skku/...` HTTP paths, `key.type == "skku_article"`, nested `key.article_no`, offset pagination, and inclusive calendar end dates unless an explicit API-versioning change is requested.

`CrawlSkkuClient` is the public high-level Python API. Parsers and source-specific services are internal implementation details.

## Cache

The cache stores parsed JSON, not raw upstream responses. It defaults to `.cache/crawl-skku/skku_cache.sqlite3` and is intentionally best-effort: cache failures must not fail a successful upstream fetch.

Use the centralized settings in `crawl_skku.cache.config`; do not add source-local environment reads. Supported variables are documented in `.env.example` and the README.

## Development

```bash
uv sync --locked
uv run ruff format --check .
uv run ruff check .
uv run mypy src
uv run python -m unittest discover -s tests -v
```

Add local, synthetic HTML or JSON fixtures for parser changes. Add cache wiring tests for source services and route/OpenAPI tests when registering a new router. Do not make normal tests depend on live SKKU services.

## Repository Rules

- Do not commit `.cache/`, `.env`, virtual environments, or generated bytecode.
- Keep upstream requests identifiable through the project-owned User-Agent.
- Keep the project unaffiliated with SKKU and respect upstream content rights and request capacity.
- Keep public documentation free of references to unrelated projects or services.
